Authentication

This API supports both public access for testing and API key authentication for production use.

🔓 Public Access

For testing and development, the API can be accessed without authentication.

  • • No API keys required
  • • Rate limited to prevent abuse
  • • Ideal for prototyping

🔒 API Key Authentication

For production use, authenticate using your API key.

  • • Higher rate limits
  • • Usage tracking
  • • Production reliability

Using API Keys

Header Authentication

Include your API key in the Authorization header:

Authorization Header
Authorization: Bearer your_api_key_here

Example with Authentication

cURL with API Key
curl -X POST "{{ base_url }}" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your_api_key_here" \
  -d '{"example": "value", "key": "data"}'
Python with API Key
import requests

url = "{{ base_url }}"
headers = {
    "Content-Type": "application/json",
    "Authorization": "Bearer your_api_key_here"
}
data = {"example": "value", "key": "data"}

response = requests.post(url, headers=headers, json=data)
print(response.json())
JavaScript with API Key
const response = await fetch('{{ base_url }}', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'Authorization': 'Bearer your_api_key_here'
    },
    body: JSON.stringify({
        example: 'value',
        key: 'data'
    })
});

const result = await response.json();
console.log(result);

Python Example
import requests
import json

# API endpoint
url = "{{ base_url }}"

# Request data

Error Codes

HTTP Status Codes

This API uses standard HTTP status codes to indicate the success or failure of requests. Here are the most common status codes you may encounter:

Status Code Status Description Common Causes
200 OK Request processed successfully Valid request with proper data formatting
400 Bad Request Invalid request format or data Malformed JSON, missing required fields, invalid data types
401 Unauthorized Authentication required or failed Missing API key, invalid API key, expired token
403 Forbidden Valid credentials but insufficient permissions API key lacks required permissions, resource access denied
429 Too Many Requests Rate limit exceeded Too many requests in time window, need to wait before retry
500 Internal Server Error Unexpected server error occurred Processing failure, database connection issues, service unavailable

Error Response Format

All error responses follow a consistent format with the following structure:

Standard Error Response Structure
{
  "error": "Error Type",
  "message": "Human-readable error description",
  "details": {
    "code": "ERROR_CODE",
    "timestamp": "2024-01-01T00:00:00Z",
    "request_id": "req_unique_identifier",
    "additional_info": "Context-specific error details"
  }
}
Error Response Fields
  • error: Brief error category (e.g., "Bad Request", "Unauthorized")
  • message: Human-readable description of what went wrong
  • details.code: Machine-readable error code for programmatic handling
  • details.timestamp: ISO 8601 timestamp when the error occurred
  • details.request_id: Unique identifier for troubleshooting (when applicable)

Retry Guidelines

  • 4xx errors: Do not retry - fix the request first
  • 429 errors: Wait for the time specified in retry_after field
  • 5xx errors: Retry with exponential backoff (max 3 attempts)
  • Network errors: Retry with exponential backoff
